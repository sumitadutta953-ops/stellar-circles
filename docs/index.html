Stellar Circles

Decentralized Rotating Savings on Soroban

A trustless, on-chain implementation of a ROSCA (Rotating Savings and Credit Association) — also known as a Tanda, Chit Fund, or Hui — where smart contracts replace the human organizer entirely.

The Problem

In traditional ROSCAs, members must trust a human organizer to collect and distribute funds fairly. This creates serious risks:

  • Risk of fraud by the organizer
  • Human error in tracking contributions
  • Disputes with no neutral arbiter
  • No transparent audit trail
✅

The Solution

Stellar Circles replaces the human organizer with Soroban smart contracts. Every contribution, payout, and membership change is:

  • Executed atomically on-chain
  • Publicly auditable on Stellar Explorer
  • Impossible to tamper with
  • Fully trustless — no intermediary needed
User Journey

How It Works

Six simple steps from circle creation to final payout — all enforced by smart contracts.

01
🏗️

Create a Circle

Set the contribution amount (in XLM), cycle length in seconds, and member cap. A unique invite code is generated.

02
🤝

Invite Friends

Share the 6-character invite code with friends. Anyone with the code can join up to the member cap.

03
🚦

Circle Starts

The circle activates automatically on-chain once the member cap is reached. No manual trigger needed.

04
💸

Everyone Contributes

Each cycle, every member sends their XLM share to the contribution vault contract. Funds are held securely on-chain.

05
🏆

Payout Triggered

Once all members have contributed, the payout contract verifies completeness and sends the full pool to that cycle's recipient.

06
🎉

Circle Completes

After every member has received one payout, the circle is marked complete. The process was fully automated and trustless.

Soroban Rust

Smart Contracts

All contracts are written in Rust using Soroban SDK v27. Located in /contracts.

🏭

circle-factory

Registry Contract

The registry contract. Stores CircleConfig structs keyed by a u64 circle ID. Entry point for creating any new savings circle.

create_circle(organizer, asset, contribution_amount: i128, cycle_length_seconds: u64, member_cap: u32) → u64

Creates a new circle on-chain, stores config, returns the new circle ID.

get_circle_info(circle_id: u64) → CircleConfig

Returns the full configuration struct for a given circle.

set_inactive(circle_id: u64, caller: Address)

Marks a circle as inactive. Only the organizer can call this.

💰

contribution

Vault & Membership Contract

Handles membership and the contribution/payout vault. Holds all XLM funds. The most critical contract in the system.

join_circle(circle_id: u64, member: Address)

Adds a member to the circle. Called automatically after creation and via invite code.

contribute(circle_id: u64, member: Address)

Member pays their share. Internally calls token::transfer to move XLM into the vault.

leave_circle(circle_id: u64, member: Address)

Removes a member and refunds their current-cycle contribution if already paid.

execute_payout(circle_id: u64, recipient: Address, amount: i128)

Sends the pooled funds to the cycle recipient. Called internally by the Payout contract.

get_members(circle_id: u64) → Vec<Address>

Returns the ordered list of members for a given circle.

has_contributed(circle_id: u64, cycle: u32, member: Address) → bool

Checks if a specific member has paid for a given cycle.

get_current_cycle(circle_id: u64) → u32

Returns the current active cycle number for a circle.

🏆

payout

Orchestration Contract

Orchestration contract. Verifies all members have contributed then triggers the vault payout. Acts as an on-chain guardian ensuring fairness.

trigger_payout(circle_id: u64)

Verifies every member has_contributed for the current cycle, then calls contribution::execute_payout to send the pool to the cycle's recipient.

🔑

passkey-factory

Wallet Deployer

Deploys per-user smart wallets tied to WebAuthn passkey credentials. Enables passwordless, seed-phrase-free wallet onboarding.

init(wallet_wasm_hash: BytesN<32>)

Initializes the factory with the passkey-wallet WASM hash to use for deployments.

deploy_wallet(salt: BytesN<32>, public_key: BytesN<65>) → Address

Deploys a new smart wallet for a user identified by their passkey public key.

👛

passkey-wallet

Per-User Smart Wallet

Smart wallet contract authorized by a passkey public key (P-256 / secp256r1). Each user gets their own deployed instance.

sign(payload: BytesN<32>, signature: Map<Symbol, Val>) → Val

Verifies a WebAuthn signature against the wallet's stored public key.

add_signer(public_key: BytesN<65>)

Adds an additional passkey signer to the wallet (e.g., recovery device).

remove_signer(public_key: BytesN<65>)

Removes a passkey signer from the wallet.

⭐

reputation

On-Chain Reputation

On-chain reputation tracking. Score is incremented with each successful contribution, building a trustworthiness record for members.

record_contribution(member: Address)

Increments the reputation score for a member after a successful contribution.

get_score(member: Address) → u32

Returns the total reputation score for a given wallet address.

🚨

default-handler

Default Resolution

Handles members who miss a contribution deadline. Protects the group from a single non-contributing member.

handle_default(circle_id: u64, member: Address)

Processes a member who has defaulted on their contribution, potentially removing them from the circle.

Contract Function Reference

All contracts are deployed to Stellar Testnet. Exact IDs are written to frontend/.env by scripts/deploy.ps1 after each deployment and can also be found in CI/CD job logs.

Contract Purpose Key Functions
CircleFactory Circle registry create_circle, get_circle_info, set_inactive
Contribution Vault & membership join_circle, contribute, leave_circle, execute_payout
Payout Payout orchestration trigger_payout
PasskeyFactory Smart wallet deployer deploy_wallet
PasskeyWallet Per-user smart wallet sign, add_signer, remove_signer
Reputation On-chain reputation record_contribution, get_score
DefaultHandler Missed contribution handling handle_default
React + Vite + TypeScript

Frontend Application

The frontend is a React SPA built with Vite and TypeScript, deployed to Vercel. It communicates with Soroban via @stellar/stellar-sdk.

Pages

🔌

WalletConnect

Handles both Passkey (WebAuthn) and Freighter wallet connection flows. First screen users see — connects them to Stellar network.

components/WalletConnect.tsx
➕

CircleCreation

Form to set contribution amount (XLM), cycle length, and member cap. On submit, calls CircleFactory::create_circle then auto-joins.

pages/CircleCreation.tsx
📊

CircleDashboard

The main circle management view. Shows member list, current cycle, contribution status, and provides Contribute / Leave buttons.

pages/CircleDashboard.tsx
🎟️

JoinCircle

Join an existing circle by entering a 6-character invite code. Calls Contribution::join_circle on-chain.

pages/JoinCircle.tsx

Services

stellar.ts Core

The backbone of all blockchain interactions. Exports CONTRACT_IDS, buildContractCall(), and submitTransaction().

Flow: Contract → TransactionBuilder → server.prepareTransaction() → server.sendTransaction() → poll server.getTransaction()

passkey.ts Auth

Handles WebAuthn credential creation and authentication. Wraps the browser's navigator.credentials API for passkey login without seed phrases.

db.ts Storage

Firebase Firestore client. Stores off-chain metadata: circle names, descriptions, invite codes, member display names, and contribution tracking per cycle.

analytics.ts Monitoring

Integrates PostHog for product analytics (wallet connects, circle creations, contributions, payouts) and Sentry for error monitoring and alerting.

Local Development

Setup & Installation

Get the full project running locally in five steps.

Prerequisites

🦀
Rust Stable

With wasm32v1-none target: rustup target add wasm32v1-none

⭐
Stellar CLI

cargo install stellar-cli --features opt

🟢
Node.js v20+

Download from nodejs.org

🔐
Freighter Wallet

Browser extension from freighter.app

1

Clone & Install

git clone https://github.com/sumitadutta953-ops/stellar-circles.git
cd stellar-circles

# Install frontend dependencies
cd frontend && npm install && cd ..
2

Configure Environment

cp frontend/.env.example frontend/.env
# Fill in VITE_FIREBASE_*, VITE_CIRCLE_FACTORY_ID, etc.
Required env vars: Firebase project config (VITE_FIREBASE_API_KEY, VITE_FIREBASE_AUTH_DOMAIN, VITE_FIREBASE_PROJECT_ID), Soroban RPC URL, and all contract IDs. See frontend/.env.example for the full list.
3

Build Smart Contracts

cd contracts
stellar contract build
# WASM files output to: contracts/target/wasm32v1-none/release/
4

Deploy Contracts to Testnet

cd scripts
./deploy.ps1   # PowerShell — writes contract IDs to frontend/.env
Requires a funded Stellar testnet account. The script automatically writes all deployed contract IDs back to frontend/.env.
5

Run Frontend Dev Server

cd frontend
npm run dev    # http://localhost:5173
Quality Assurance

Testing

Three-tier testing strategy: smart contract unit tests, TypeScript type safety, and full end-to-end browser automation.

🦀

Smart Contract Tests

Rust unit and integration tests for all Soroban contracts using the Soroban test SDK.

cd contracts
cargo test --workspace
🔷

TypeScript / Lint

Full TypeScript type checking and oxlint linting of the React frontend.

cd frontend
npx tsc --noEmit   # type check
npm run lint       # oxlint
🎭

End-to-End (Playwright)

Automated browser tests using Playwright Chromium covering key user flows.

cd frontend
npx playwright install --with-deps chromium
npm run build
npx playwright test

Contributing

Stellar Circles is open source under Apache 2.0. Contributions are welcome!

Smart Contracts (Rust)

  1. Edit the relevant contract in contracts/<name>/src/lib.rs
  2. Build: cd contracts && stellar contract build
  3. Test: cargo test --workspace
  4. Lint: cargo clippy --all-targets -- -D warnings
  5. Format: cargo fmt --all

Frontend (TypeScript/React)

  1. Edit files in frontend/src/
  2. Type-check: npx tsc --noEmit
  3. Lint: npm run lint
  4. Build: npm run build

Commit Convention

Use Conventional Commits:

feat(contracts): add reputation scoring
fix(frontend): handle Freighter rejection
ci: add cargo-audit security scanning
docs: update contract reference in README
chore: bump soroban-sdk to v28
